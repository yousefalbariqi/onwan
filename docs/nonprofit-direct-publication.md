# متطلبات النشر المباشر للجمعيات

قرار المالك المعتمد في 1 نوفمبر 2026. يلغي هذا القرار شروط المعاينة الخاصة ومنع النشر السابقة لمسار nonprofit فقط. مراجعة الكود مكتملة؛ السلوك الجديد أدناه لم يُنفذ بعد، ولم يُطبق ترحيل أو نشر إصدار ضمن هذه المراجعة.

## النطاق

- الحسابات المنشأة من بوابة `nonprofit.onwan.link` أو مسارات `/nonprofit/*` والمميزة في الخادم بـ `users.account_kind = 'nonprofit'`.
- زيارة البوابة بحساب عادي لا تحوله إلى هذا المسار. لا تتغير رحلة العملاء العاديين أو الشركاء أو الدفع والنشر لديهم.
- تبقى ضوابط الجلسات والملكية وصيغة البيانات وتفرد الرابط وحدود الاستخدام وحماية التسجيل. المؤجل هو إلزام تأكيد البريد للنشر فقط.

## المتطلبات المعتمدة

| الرمز | المتطلب |
| --- | --- |
| NP-01 | عند نجاح تسجيل جمعية تنشأ صفحتها منشورة برابط فعلي فريد. لا تنتظر اكتمال التصميم أو طلب التفعيل أو الإدارة أو الدفع أو تأكيد البريد. |
| NP-02 | الرابط والـQR والمشاركة يعملون من البداية ويقودون للصفحة نفسها. Apple Wallet يتبع إعداداته التقنية الحالية، ولا يشترط طلب التفعيل لعمل رابط البطاقة. |
| NP-03 | «حفظ التعديلات» يحدث الصفحة المنشورة. المعاينة والتعديلات غير المحفوظة تبقى في المحرر. الحفظ لا يعيد تشغيل صفحة أوقفتها الإدارة. |
| NP-04 | تظهر الحالة الحقيقية «منشورة» بجانب الرابط في موضع مناسب؛ وعند الإيقاف تظهر «موقوفة». |
| NP-05 | الإجراء الموجه للعميل «طلب التفعيل» بدل إجراء النشر. هو طلب متابعة وتواصل فقط، والصفحة تعمل قبله وبعده. لا يثبت دفعًا أو اشتراكًا مدفوعًا أو نشرًا جديدًا. |
| NP-06 | الطلب مرتبط بالجمعية وبيانات التواصل ويظهر للإدارة. تكرار الإرسال لا ينشئ طلبات مكررة، وفشل إشعار البريد لا يفقد الطلب ولا يوقف الصفحة. |
| NP-07 | الإدارة تتواصل لتحديد السعر واستكمال التفعيل التجاري. حالة الطلب مستقلة عن حالة الصفحة وعن البريد والتحصيل. |
| NP-08 | للإدارة إيقاف الصفحة وإعادة تشغيلها مع السبب وسجل التدقيق وحفظ البيانات والتصميم، وبصلاحيات الخادم الحالية. |
| NP-09 | تأكيد البريد اختياري حاليًا، ولا يمنع التحرير أو الحفظ أو النشر أو تقديم الطلب أو إعادة التشغيل الإداري. لا يُعلّم البريد كمؤكد تلقائيًا. تبقى رموز أمان تغيير بيانات الحساب واستعادة الدخول. |
| NP-10 | لا يضاف مؤقت تجربة أو إيقاف تلقائي بهذا القرار. طُرحت مدد يومين وثلاثة أثناء النقاش؛ القائمة النهائية اعتمدت النشر المباشر وتحكم الإدارة. مدة ملزمة أو إيقاف آلي يحتاج قرارًا منفصلًا. |

## رحلة الجمعية

بوابة الجمعيات ← تسجيل ورابط فعلي ونشر مباشر ← إعداد الشعار والمحتوى ← المحرر ← حفظ التعديلات ← فتح الرابط ومشاركة QR ← طلب التفعيل ← استلام الإدارة ومتابعتها ← استمرار الصفحة أو إيقافها وإعادة تشغيلها بقرار الإدارة.

فتح الصفحة ومشاركتها قبل اكتمال المحتوى وقبل الطلب مقصود ومعتمد؛ خطوات الإعداد الحالية لا تمنع النشر.

## نصوص الواجهة

- الحفظ: «حفظ التعديلات»؛ المتابعة: «طلب التفعيل».
- بجانب الرابط: «منشورة» أو «موقوفة» وفق حالة الخادم.
- بعد الطلب: «وصل طلب التفعيل، وسنتواصل معكم.» ويمكن إضافة «صفحتكم منشورة والرابط والباركود يعملان» إذا كانت منشورة فعلًا؛ لا تعرض هذه العبارة لصفحة موقوفة.
- البريد غير المؤكد: تذكير اختياري، دون «مطلوب لنشر الصفحة».
- تزال «معاينة خاصة»، و«لا نشر للصفحة»، و«تعديلاتكم التالية تبقى مسودة» عندما تصف حالة الصفحة العامة أو الحفظ الصريح؛ يبقى وصف المسودة صحيحًا للتعديلات غير المحفوظة.

## تعارضات الكود وخطة التعديل

| الموضع | الموجود حاليًا | المطلوب |
| --- | --- | --- |
| `api/auth/signup.ts` | يتجاوز حجز الاسم للجمعية ويخزن `suggested_username` فقط، والصفحة مسودة. | فحص التوفر وتثبيت اسم فعلي ونشر الجمعية داخل معاملة التسجيل نفسها، دون دفع أو اشتراك مصطنع. فحص الواجهة وحده لا يكفي. |
| `api/_lib/page.ts` | المالك يرى الاسم المقترح؛ الجمهور يبحث في `usernames` ويستبعد المسودات. | توحيد الرابط المعروض مع رابط عام مملوك فعليًا؛ لا نفتح الأسماء المقترحة غير المحجوزة للجمهور. |
| `database/phase25-nonprofit-requests.sql` | `nonprofit_publication_guard` يمنع النشر والاشتراك النشط قبل `nonprofit_activated_at`. | ترحيل تصحيحي جديد يفصل النشر عن التفعيل التجاري. لا نضع وقت تفعيل تجاري وهميًا ولا نسقط حماية الاشتراكات عرضًا، ولا نعدل ترحيلًا قديمًا بدل التصحيح. |
| `api/_lib/account.ts` | `activateSubscription` يشترط تأكيد بريد الجمعية ويجمع الدفع وتثبيت الاسم والنشر. | إزالة اشتراط التأكيد للجمعيات في المسار المعني، وفصل النشر المباشر عن إثبات الدفع. تفعيل الاشتراك يبقى عبر إجراء موثوق. |
| `api/_lib/accountActions.ts` و`NonprofitSettings.tsx` | تغيير الرابط يتبع الاسم غير المثبت قبل الدفع. | مواءمة الرسائل والسياسة مع وجود رابط عام؛ لا يغير رابط قائم أو وجهة QR بصمت. |
| `NonprofitBuilder.tsx` و`Builder.tsx` | محرر الجمعيات يستخدم `staffEdit` بعنوان معاينة خاصة وإجراء متابعة لطلب عرض؛ بعض المشاركة مخفية في هذا النمط. | طلب تفعيل مع حالة نشر ومشاركة وحفظ يحدث الجمهور، دون تغيير تحرير الموظف أو العميل العادي. |
| `NonprofitPortal.tsx` | التأكيد يقول لم تنشر الصفحة والتعديلات التالية مسودات، مع تنبيه تأكيد البريد للنشر. | تحويل رحلة الطلب ونصوصها إلى متابعة مستقلة عن النشر، مع بقاء بيانات التواصل ومنع التكرار. |
| `NonprofitSettings.tsx` | QR مشروط بالنشر والحساب حاليًا مسودة، والبريد مطلوب للنشر. | حساب منشور من البداية يظهر QR والحالة بجانب الرابط والبريد اختياري. يبقى فحص الحالة للصفحات الموقوفة. |
| `api/_lib/nonprofit.ts` | لقطة تصميم ثابتة وإشعار إدارة يقول لم تنشر الصفحة. | طلب تفعيل وإشعار مطابقان للحالة الفعلية؛ لقطة الطلب للتوثيق منفصلة عن أحدث نسخة منشورة. |
| `api/_lib/nonprofitAdmin.ts` | تعرض الطلبات فقط، لا الجمعيات التي لم ترسل طلبًا. | متابعة المنشور دون طلب أيضًا، مع تمييزه عن الطلبات المقدمة. |
| `api/_lib/admin.ts` | الإيقاف وإعادة التشغيل موجودان بسجل تدقيق، لكن مشغّل النشر القديم قد يمنع إعادة التشغيل. | إعادة استخدام الصلاحيات، ومعالجة المشغّل وإبطال التخزين المؤقت عند تغيير الحالة. |
| `tests/nonprofit-workflow.integration.cjs` و`tests/worker.test.cjs` | توقعات للمسودة ومنع النشر؛ التكامل يتوقع أيضًا منع طلب العرض قبل التأكيد رغم أن كود الطلب الحالي لا يشترطه. | تحديث اختبارات السلوك والتمييز عن العميل العادي، وإصلاح التوقع القديم بدل اعتباره متطلبًا. |

ملفات الواجهة المذكورة أعلاه تقع تحت `src/app/pages` و`src/app/components`. `PATCH /api/page/me` يحفظ المحتوى ويبطل التخزين المؤقت بالفعل، لكن `savePageData` لا ينقل المسودة إلى منشورة. تغيير نص الزر أو إظهار QR وحده لا يطبق القرار.

## توافق المتطلبات القديمة

- `ACCT-02` وقرار تثبيت الاسم بعد الدفع يستثنى منهما nonprofit فقط بقدر النشر المباشر والرابط الحقيقي؛ لا تتغير بقية الحسابات.
- `ACCT-03` وتفرد الاسم يبقيان؛ `PAGE-07` يبقى: الحفظ الصريح يحدث الجمهور والمعاينة مستقلة.
- تأكيد البريد الاختياري يتوافق مع سماح `ACCT-04` بالنشر قبل التأكيد؛ شرط التأكيد المانع جاء من مسار الجمعيات اللاحق.
- تحكم الإدارة مع حفظ البيانات يتوافق مع مبدأ `SUB-06..08`، ولا يضاف توقف آلي.
- تبقى ملكية الحسابات، طلب واحد وقفل منع التكرار، لقطة التصميم، حماية مراجع الملفات، إشعار الإدارة وإعادة المحاولة، وعدم ادعاء دفع لم يحدث.
- ربط نطاق خاص ما زال منفصلًا ويتطلب الملكية وDNS والشهادة. لا يشمله النشر المباشر لنطاق عنوان.

## ترحيل الحسابات الحالية

يفحص التنفيذ أسماء الجمعيات المقترحة والحجوزات والأسماء المثبتة قبل نقل أي سجل. الاسم المقترح لم يكن حجزًا وقد يتعارض مع اسم عميل آخر؛ تحفظ التعارضات للمعالجة دون الاستيلاء على اسم قائم أو تغيير رابط بصمت.

تحدث المسودات المؤهلة دون فتح صفحات موقوفة أو حسابات محظورة أو تغيير العملاء العاديين. لا تمس بيانات الطلبات أو المحتوى أو الاشتراكات المدفوعة. تفصل سياسة تغيير الرابط العام عند التنفيذ بما يحفظ الروابط المشتركة.

## اختبارات القبول عند التنفيذ

1. تسجيل جمعية ببريد غير مؤكد ينتج صفحة عامة ورابطًا فريدًا دون طلب أو دفع أو اشتراك مصطنع.
2. تسجيلان متزامنان للاسم نفسه لا ينتجان الرابط نفسه، وفشل المعاملة لا يترك حسابًا ناقصًا.
3. زائر يفتح الرابط والـQR قبل اكتمال الإعداد والطلب؛ العناصر المخفية وغير المكتملة تبقى مخفية وفق قواعد المحتوى الحالية.
4. الحفظ يحدث HTML وAPI والنسخ المؤقتة؛ التعديل غير المحفوظ لا يصل للجمهور.
5. طلب التفعيل مرة واحدة رغم التكرار؛ فشل الإشعار لا يوقف الصفحة ولا يسجل دفعًا.
6. الإدارة ترى الجمعيات دون طلب، وتوقف وتعيد التشغيل مع سجل تدقيق ومحتوى محفوظ.
7. الحفظ والطلب وتسجيل الدخول لا يعيدون تشغيل صفحة موقوفة؛ البريد غير المؤكد لا يمنع الإعادة الإدارية.
8. العملاء العاديون والشراء والشركاء لا يحصلون على هذا الاستثناء، وزيارة البوابة لا تغير نوع الحساب.
9. الترحيل يعالج تعارض الأسماء على قاعدة اختبار مستقلة؛ لا تنفذ اختبارات الترحيل على الإنتاج.

## حفظ التجربة لنسخها وتصويرها لاحقًا

القائمة التالية توثق التجربة كاملة؛ لا تنشئ نسخة ثانية الآن:

1. فتح بوابة الجمعيات والتسجيل باسم جمعية ورابط متاح.
2. إعداد المنصات والشعار والنبذة وفتح المحرر.
3. إظهار «منشورة» والرابط وفتحه من جهاز آخر قبل الطلب.
4. تعديل التصميم وحفظه وإظهار التحديث للعامة.
5. عرض QR والمشاركة وApple Wallet عند توفر بيئة مهيأة.
6. طلب التفعيل وتأكيد الاستلام مع استمرار الصفحة.
7. الإدارة: الطلب وبيانات التواصل والمتابعة، والجمعيات التي لم ترسل طلبًا.
8. الإيقاف وحالته ثم إعادة التشغيل بالمحتوى نفسه.

عند طلب نسخ التجربة لاحقًا، تنسخ الرحلة وإعداداتها ونصوصها وحالاتها واختبارات قبولها؛ لا تنسخ حسابات العملاء أو بياناتهم أو الأسرار أو الطلبات الفعلية.
