# تنفيذ إدارة الجمعيات وتجهيز الإصدار

نُفذت خطة `nonprofit-admin-plan.md` محليًا في 1 نوفمبر 2026. لم يُطبق الترحيل على الإنتاج ولم يُنشر إصدار ضمن هذا العمل.

## ما تغير

- تبويبة «الجمعيات» نفسها: أعداد الحالات، البحث، الترشيح، تقسيم الصفحات، قائمة حاسوب وبطاقات جوال، وحالات الانتظار والفشل والفراغ.
- ملف الجمعية يجمع الاتصال والموظف المتابع والملاحظات وأحدث تصميم ولقطة الطلب الأصلية وسجل المتابعة. محرر الموظف يرجع للطلب مع البحث والمرشح المحفوظين.
- عرض سعر قابل للتعديل، يتضمن السعر ومدة الاستضافة بالأشهر والخدمات والملاحظات. يبدأ نموذج العرض الجديد بالقيم الموجودة في رحلة العميل (430 ريال و36 شهرًا) ولا يحفظها تلقائيًا.
- نسخ النسخة المحفوظة للإرسال اليدوي ثم تسجيل إرسالها. النسخة المرسلة محفوظة بصورة مستقلة عن أي تعديل لاحق لمسودة العرض، ويسجل تاريخ كل إجراء.
- تأكيد استلام التحويل: المبلغ الفعلي المطابق للعرض المرسل، المرجع، وتاريخ التحويل. الدفع يسجل مرة واحدة في `payments`، مع رابط فريد من الطلب إليه.
- تفعيل مستقل بعد التحصيل، مع مراجعة الرابط والمدة. تثبيت الرابط والنشر وتسجيل استضافة الجمعية والتدقيق تتم بمعاملة واحدة. فشل التفعيل لا يكرر التحصيل المسجل.
- الاستضافة الخاصة بالجمعيات في `nonprofit_hosting` بمدة العرض الفعلية؛ لا ينشأ اشتراك شهري/سنوي مصطنع. بقية باقات العملاء وتجديداتهم لم تتغير. لا يوجد إيقاف آلي بانتهاء المدة؛ الإدارة تتابعها يدويًا.
- الإيقاف وإعادة التشغيل من الملف نفسه مع السبب والرسالة والسجل. لا يتجاوز التفعيل حسابًا محظورًا أو صفحة موقوفة.
- بعد التفعيل تظهر أدوات الرابط والباركود والمحفظة. طلب بطاقة الموظف يستخدم صلاحية الإدارة ورابط الصفحة العامة، ولا يعتمد جلسة مستفيد قد تخص شخصًا آخر.

## سلامة البيانات والصلاحيات

جميع الإجراءات الجديدة تشترط جلسة موظف فعال وتقيّد البيانات بحساب nonprofit في الخادم. للموظف تعديل المحتوى وتأكيد التحويل والتفعيل كما اعتمد المالك، وتبقى صلاحيات بقية الإدارة كما هي.

كل إجراء تجاري يقفل الطلب والحساب والصفحة ويفحص رقم إصدار الطلب؛ بيانات قديمة أو طلبان متزامنان لا يكرران التحصيل. سجل المتابعة وسجل التدقيق جزء من المعاملة نفسها. عند تثبيت الرابط، يفحص توفره مع قفل مصادر الأسماء لمنع تعارض اسم ثابت مع حجز في جدول آخر. اسم مملوك أو محجوز للغير لا يؤخذ.

الطلبات القديمة `agreed` تبقى متفقًا عليها دون تحويلها إلى مدفوعة أو منشورة. عليها إعداد عرض وتسجيل إرساله ثم تأكيد التحويل قبل التفعيل. محتوى الطلب الأصلي لا يستبدل عند تعديل الصفحة.

لا إرسال آلي لعروض الأسعار أو رسائل تسويق، ولا رفع إيصالات إلى وسائط عامة. النظام ينسخ نص العرض ويسجل أن الموظف أرسله خارج النظام. إشعار طلب الجمعية للإدارة يبقى كما كان.

## قاعدة البيانات وترتيب الإطلاق

1. خذ نسخة احتياطية لقاعدة الإنتاج وفق إجراءات المشروع.
2. طبّق `database/phase29-nonprofit-admin.sql` قبل نشر الكود الجديد، بعد الترحيلات السابقة حتى phase28.
3. الترحيل يضيف حقول العرض والتحصيل والمتابعة والإصدار، ويوسع حالات الطلب، ويضيف `nonprofit_request_events` و`nonprofit_hosting` مع RLS. لا ينشر صفحات ولا ينشئ تحصيلًا أو يغير الطلبات القديمة تلقائيًا.
4. انشر Worker وملفات الواجهة معًا. للتراجع يمكن إعادة الإصدار السابق دون حذف الحقول أو السجلات الجديدة؛ لا تُعد تطبيق ترحيل قديم لإزالة بيانات العمل الجديدة.
5. تحقق من طلب موجود على الإدارة، ثم اختبر التفعيل على بيئة اختبار قبل أي تفعيل فعلي. جهّز توقيع Apple Wallet لعمل إضافة البطاقة.

## التحقق

- اختبارات PostgreSQL الحقيقية: تطبيق الترحيل مرتين دون تلف البيانات، بقاء agreed دون دفع، منع تجاوز الحالات، تجميد العرض المرسل، تأكيدان متزامنان ينتجان تحصيلًا واحدًا، تعارض اسم وحجز، منع نشر صفحة موقوفة، التراجع الكامل عند فشل سجل التدقيق، تفعيل 36 شهرًا، حفظ المحتوى والإيقاف والإعادة، عزل العميل العادي، ونتائج البحث وتقسيم الصفحات.
- تشغيلها: `npm run test:nonprofit-admin`. اختبار PostgreSQL يتخطى التنفيذ دون `NONPROFIT_ADMIN_TEST_DATABASE_URL`، ويرفض قاعدة غير محلية أو لا يبدأ اسمها بـ `onwan_test_`. لا يستخدم DATABASE_URL أو بيانات الإنتاج.
- اختبارات صلاحيات API تمنع المستفيد من استخدام إجراءات الجمعيات الإدارية الجديدة. الاختبارات العامة والبناء وTypeScript وWorker جزء من تحقق الإصدار.
- اتصال المتصفح غير متاح في الجلسة؛ الفحص البصري التفاعلي على الحاسوب والجوال وتجربة الإضافة على آيفون لم يُنفذا. لا يُعتبر نجاح البناء بديلًا لهذه الخطوة قبل الإطلاق العام.

نتائج التنفيذ: نجح فحص TypeScript وبناء الإنتاج، و63 اختبارًا للمحتوى والطلبات وواجهات Worker وصفحة الجمعيات، ثم 13 اختبارًا في أمر إدارة الجمعيات يتضمن 9 اختبارات PostgreSQL فعلية، و37 اختبارًا في أمر Worker النهائي (تتداخل بعض الاختبارات بين الأوامر). نجح فحص تنسيق التغييرات. أوقف خادم PostgreSQL الاختباري بعد انتهاء الفحص.
