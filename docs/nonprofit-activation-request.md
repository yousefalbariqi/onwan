# مسار حفظ التصميم وطلب عرض السعر للجمعيات

القرار الأحدث للمالك في 1 نوفمبر 2026، بعد التراجع عن النشر المباشر. يستبدل هذا المستند قرار `nonprofit-direct-publication.md` في كامل ما يتعارض معه. التنفيذ محلي في الكود؛ لا يعني ذلك نشر إصدار على الإنتاج.

## الرحلة المعتمدة والمنفذة

1. التسجيل من بوابة nonprofit ثم إعداد بيانات الجمعية والتصميم. الحساب العادي لا يتحول إلى جمعية عند زيارة البوابة.
2. الحفظ داخلي: لا ينشر صفحة جديدة، ولا يمنح اشتراكًا أو يثبت دفعًا. التعديلات غير المحفوظة تبقى في المحرر. الصفحات المفعلة سابقًا تحتفظ بسلوكها القائم؛ لا يسحب التعديل نشرها.
3. «النشر والتالي» يحفظ التصميم أولًا. عند فشل الحفظ يبقى العميل في المحرر؛ عند نجاحه ينتقل إلى خطوة تأكيد البريد إن لم يؤكد سابقًا.
4. تأكيد البريد باستخدام الرمز الحالي؛ لا إعادة لطلب كلمة المرور. فتح رابط الملخص مباشرة لا يتجاوز التحقق، والخادم يرفض تقديم طلب عرض دون بريد حساب مؤكد.
5. بعد التأكيد يظهر ملخص التصميم والرابط والسعر الموجود سابقًا (430 ريال) وهدية استضافة ثلاث سنوات، والخدمات المجانية: المحرر وQR وApple Wallet والتواصل والدعم. لا تغيير في الأسعار أو شروط العرض بهذا التنفيذ.
6. يظهر QR أسود على أرضية بيضاء مع هامش أربع وحدات، ويمكن تنزيله. تظهر إضافة بطاقة Apple Wallet عبر رابط بطاقة موقّعة من الخدمة الحالية عند تهيئتها؛ عند تعذر التجهيز يظهر تنبيه وإعادة محاولة. البطاقة والرمز لا ينشران الصفحة.
7. حالة الصفحة غير المفعلة «بانتظار استكمال التفعيل». يوضح الملخص أن إتاحة الصفحة العامة بعد استكمال التفعيل، ولا يدعي أن رابطًا غير منشور يعمل للعامة.
8. الإجراء الأساسي بقفل: «طلب عرض سعر لتفعيل الحساب». بيانات الجمعية ومسؤول التواصل ووسائل الاتصال والملاحظات والنطاق الاختياري تبقى في النموذج الحالي.
9. الإرسال يحفظ نسخة التصميم مع الطلب في الإدارة الحالية، مرة واحدة رغم تكرار الإرسال، ويحاول إشعار الإدارة. فشل الإشعار لا يفقد الطلب. التأكيد: «وصل طلبكم، وسنتواصل معكم لاستكمال التفعيل.»
10. الطلب لا ينشر ولا يحصّل ولا يفعّل حسابًا. تعديلات التصميم التالية لا تستبدل لقطة الطلب المرسلة. نُفذت لاحقًا واجهة إدارة موحدة وتفعيل بعد التحصيل؛ راجع `nonprofit-admin-release.md`. إرسال طلب العميل نفسه لا يفعّل الحساب.

## حدود القرار

- المسار لحسابات `account_kind = 'nonprofit'` فقط؛ لا تغيير في مسار العميل العادي أو الشريك أو الدفع.
- لا تشغيل عام خفي، ولا تفعيل تلقائي لثلاثة أيام، ولا مؤقت إيقاف. المدة ذُكرت كخيار ولم تُعتمد في الطلب النهائي.
- لا ترحيل قاعدة بيانات مطلوب: تبقى حماية النشر الإداري الموجودة، وحسابات الجمعيات الجديدة تبدأ مسودات كما كانت.
- تأكيد البريد شرط للمتابعة والطلب، وليس للتصميم أو الحفظ الداخلي. يقرأ الخادم التأكيد مع قفل سجل الحساب لمنع التسابق مع تغيير البريد.
- Apple Wallet يحتاج إعداد توقيع صالحًا؛ لا تستبدل البطاقة الموقعة بصورة ولا تظهر رسالة نجاح عند فشل تجهيزها.

## مواضع التنفيذ

- `src/app/pages/NonprofitBuilder.tsx`: عنوان الحفظ الداخلي وزر «النشر والتالي»؛ نواة المحرر تحفظ قبل المتابعة كما كانت.
- `src/app/pages/NonprofitPortal.tsx`: بوابة تأكيد البريد، الملخص، طلب العرض والتأكيد؛ عرض الباركود والبطاقة قبل الطلب وبعده.
- `src/app/components/EmailVerifyChip.tsx`: دعم فتح خطوة التحقق تلقائيًا ونص مخصص، مع بقاء الاستخدام الافتراضي لبقية الحسابات.
- `src/app/components/NonprofitSummaryAssets.tsx`: تجهيز QR وبطاقة المحفظة، معالجة الأخطاء وإعادة تجهيز رابط Wallet قبل انتهاء صلاحيته.
- `src/app/components/NonprofitSettings.tsx`: توضيح أن تأكيد البريد مطلوب للمتابعة وطلب العرض.
- `api/_lib/nonprofit.ts`: إلزام التأكيد في الخادم قبل إنشاء الطلب مع الحفاظ على الملكية والتكرار والإشعار ولقطة التصميم.
- `tests/nonprofit-request.test.cjs`: رفض تجاوز التحقق، حفظ الطلب دون نشر أو دفع، منع التكرار، تحمل فشل الإشعار وعزل العميل العادي.

## قائمة تجربة للتصوير وإعادة الاستخدام

تسجيل جمعية ← إعداد الشعار والمحتوى ← تعديل وحفظ داخلي ← «النشر والتالي» ← رمز البريد ← الملخص والسعر والخدمات ← تنزيل QR وإضافة Wallet على آيفون مهيأ ← تعبئة بيانات المسؤول ← طلب عرض السعر ← تأكيد الاستلام ← ظهور الطلب ونسخة التصميم في الإدارة الحالية.

للتحقق: رفض رمز خاطئ وإعادة الإرسال، إلغاء التحقق والعودة للمحرر مع بقاء التصميم، دخول مباشر للملخص دون تأكيد، فشل الحفظ دون انتقال، تكرار إرسال الطلب، تعذر Wallet، وحساب عادي لا يدخل مسار الجمعيات. لا تستخدم بيانات عملاء أو ترسل بريد إنتاج لإجراء الاختبارات.

## نتائج التحقق المحلي

- نجح `npm run check:worker` وبناء الإنتاج `npm run build`.
- نجح 33 اختبارًا عبر `node --test tests/nonprofit-request.test.cjs tests/nonprofit-landing.test.cjs tests/page-content.test.cjs`.
- نجح `npm run test:worker`: عدد 33 اختبارًا يشمل تشغيل الحزمة في workerd. احتاج منفذ localhost خارج قيود العزل؛ لا نشر فعلي ضمن هذا الأمر.
- نجح `git diff --check`. حُدث اختبار صفحة الجمعيات ليتوافق مع نصها الحالي بدل نص محذوف سابقًا.
- تعذر الفحص البصري لأن اتصال المتصفح غير متاح. لم تختبر إضافة بطاقة فعلية على آيفون ولم تُرسل رسائل اختبار إنتاج أو تُغير قاعدة البيانات.
