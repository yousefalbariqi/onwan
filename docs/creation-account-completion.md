# إكمال الحساب بعد التصميم

المسار الرسمي: القوالب ← حفظ البداية بالبريد والتحقق ← المصمم ← «حفظ صفحتي» ← `/signup?step=complete` ← حفظ الحساب ← `/plan-selection`.

الشاشة تعيد استخدام قواعد `shared/accountRules.ts` لكلمة المرور والجوال، ومكون إظهار/إخفاء كلمة المرور، وتحويل الاسم العربي لاقتراح الرابط، وواجهة فحص توفر الرابط الحالية، وخدمة `/api/auth/signup` نفسها. تبقى رحلتا التسجيل القديمة والجمعيات متاحتين؛ لا تُستبدل صفحاتهما بهذه المرحلة.

يعرض البريد الموثق والاسم والرابط مع خيارات التعديل. التحقق من توفر الرابط للاستعراض فقط؛ الحجز الحقيقي يتم عبر `reserveUsername` داخل معاملة التسجيل. حالات التحميل والخطأ لا تُزيل التصميم. الرجوع يحفظ تغيير الاسم في مسودة المصمم، وتُستعاد حقول النموذج غير السرية داخل التبويب. لا تُخزّن كلمة المرور في استعادة النموذج.

## ضمانات الخادم

- لا يُعتمد ادعاء توثيق البريد من الواجهة. جلسة `creation` الموقعة ومطابقة البريد والمسودة شرط نقل إثبات ملكية البريد إلى الحساب.
- تعديل البريد يحتاج جلسة المسودة الحالية ورمزًا للبريد الجديد. يبقى البريد القديم حتى نجاح الإثبات وتحديث نفس سجل المسودة. يُرفض بريد لحساب قائم ولا تُنقل المسودة إلى حسابه.
- إنشاء المستخدم، حجز الرابط، إنشاء الصفحة، حفظ كامل التصميم في `pages.draft_json`، نقل إثبات البريد وتسجيل الموافقة تتم في معاملة واحدة. لا دفع ولا نشر ضمنها.
- يُقفل سجل المسودة لمنع إكماله مرتين. تكرار التسجيل بعد ضياع الرد يعيد الحساب نفسه فقط مع كلمة مرور الحساب الصحيحة، وضمن حماية محاولات الدخول. لا تُنشأ نسخة ثانية.
- بعد الإكمال تُرفض عمليات التحرير والرفع بجلسة المسودة؛ يُستخدم حساب العميل. تُحفظ علاقة المسودة بالحساب لحماية إعادة المحاولة وسجل الموافقة، وتُحذف معه عند حذف الحساب.
- شاشة البريد السابقة لا تسجل موافقة تغطي إنشاء الحساب. لذلك تظهر موافقة صريحة هنا ما لم يرجع الخادم موافقة مسجلة بإصدار `account-v1`. لا نعتمد checkbox محفوظًا محليًا كدليل موافقة سابقة.

## متطلبات التشغيل والتحقق

تطبيق `database/phase33-creation-account-completion.sql` بعد phase32 **قبل نشر الكود**. لم يُطبق الترحيل على قاعدة بيانات خلال هذا العمل. تبقى متطلبات البريد وTurnstile والتخزين من المرحلة السابقة.

الاختبارات الجديدة تغطي استعادة الهوية واقتراح الرابط، قيود البيانات والموافقة، نقل التصميم الكامل مع البريد الموثق، تراجع المعاملة عند تعارض الرابط، إعادة محاولة التسجيل وتعديل البريد مع ثبات المسودة. هذه الاختبارات تستخدم خدمات محاكاة؛ يجب أيضًا فحص ترحيل SQL وإرسال البريد والتسجيل الحقيقي في بيئة اختبار مجهزة. الفحص البصري التفاعلي لم يُنجز لتعذر أداة المتصفح في هذه الجلسة.
